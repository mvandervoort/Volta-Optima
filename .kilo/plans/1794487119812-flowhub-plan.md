# FlowHub — modernisering Brooks 5850S bediening

## Doel

Vervang de verouderde Brooks SmartDDE-applicatie door een headless Linux-service met web-UI voor het uitlezen, instellen en configureren van Brooks 5850S mass flow controllers via een Waveshare RS232/485-to-Ethernet converter. De service draait op een Linux industrial PC; Windows-clients gebruiken alleen een browser.

## Vaste beslissingen

- Geen ElectroBun of Tauri: desktop-shells, niet geschikt voor headless + webclients.
- Backend: Bun + Hono (REST + WebSocket), `bun:sqlite`.
- Frontend: React + Vite + TypeScript, UI in het Nederlands.
- Deployment: Docker Compose met `app` en Caddy; HTTPS via Caddy internal CA.
- Eén RS-485-bus, maximaal ~10 devices, 1 Hz polling per device.
- Eén master op de bus: alleen de nieuwe service opent de TCP-verbinding. SmartDDE wordt volledig vervangen en mag niet gelijktijdig op dezelfde bus draaien.
- Protocol: Brooks S-protocol (HART-based) volgens `541-C-053-AAA`. Geen Modbus.
- Converter: wordt eenmalig handmatig via de webinterface geconfigureerd (statisch IP, TCP server, transparante hex-mode, baud/parity/stopbits conform 5850S). De app opent alleen de TCP-verbinding en beheert de converter niet.
- Auth: operator/admin-login; minimale user-admin (aanmaken, deactiveren, rol wijzigen); geen wachtwoordreset/self-service.
- Valve override: operator mag normal/open/closed met expliciete bevestiging; elke actie wordt geaudit.
- Baudrate: alleen via dipswitch en converterconfig; de app schrijft nooit command #123.
- Write-protect: de 5850S ondersteunt #128 niet (manual: "not supported … has no effect"). De UI toont capability-gated "niet ondersteund"; geen dode toggle. Zie `docs/s-protocol.md` §6.
- Protocolreferentie: `docs/s-protocol.md` is gezaghebbend voor de codec (byte-layouts, code-tabellen, statusbytes), opgesteld uit `541-C-053-AAA` (GF40/GF80) en cross-check SLA5800 + 4800-capture.
- Device-naam, enabled en poll-interval: admin-only in de UI, opgeslagen in SQLite. `config.json` blijft read-only voor converter/bus/adressen.
- Backup: dagelijkse SQLite-backup + restore-documentatie.
- Niet gereguleerd: geen GMP/21 CFR Part 11, e-signatures of validatiedossier; audit is operationeel.
- Geen veiligheidsfunctie (SIL); noodstop en procesveiligheid blijven hardwarematig.
- Nieuwe GitHub-repository `flowhub` (private) onder `mvandervoort`: `https://github.com/mvandervoort/flowhub.git`. De **child Cloud Agent** bouwt de projectmap in zijn eigen worktree; `/workspace/app` (Volta-Optima, publiek) blijft de planning-workspace en wordt niet de doel-repo.
- Git-flow: direct op `main` committen en pushen; geen PR-flow voor de scaffold.
- CI: GitHub Actions met lint, typecheck, test en Docker build.
- Eerste commit: scaffold + docs + dit plan.

## Architectuur

```
Windows/lab browser ──HTTPS──> Caddy ──> Hono/Bun app ──TCP transparant──> Waveshare converter ──RS-485──> 5850S devices
                                      │                    │
                                      │                    └─ polling engine (1 Hz, sequentieel, 1 transactie tegelijk)
                                      ├─ REST: auth, users, devices, setpoint, valve override, config, audit
                                      └─ WebSocket: live device-state (1 Hz push)
```

- De Bun-service is de enige master op de RS-485-bus en bezit de TCP-verbinding.
- De UI praat alleen met de service; nooit direct met de converter.
- Live data via WebSocket; schrijfacties via REST met audit.
- SQLite in een Docker-volume; `config.json` read-only gemount.

## Datamodel

`config.json` (read-only, door deploy/beheer):

- converter: host, port, baudrate, data bits, parity, stop bits.
- bus: poll-default, device-lijst `{id, address (hex; long-frame 5 bytes of short-frame 1 byte), initialName}`.
- geen wachtwoorden of sessies.

SQLite (volume):

- `users(id, username unique, password_hash, role, active, created_at, last_login)`
- `devices(id, config_id, name, enabled, poll_interval_ms, created_at, updated_at)`
- `device_state(device_id, flow, unit, setpoint, setpoint_unit, valve_position, temperature, totalizer, status_bits, online, last_seen, updated_at)` — runtime-state, geen trendgeschiedenis.
- `audit(id, ts, user_id, username, role, action, device_id, field, old_value, new_value, success, detail)`
- `settings(key, value)` — schema-versie.

Migraties: `src/server/db/migrations/*.sql`, uitgevoerd bij startup. SQLite in WAL-modus.

## Device discovery en resolutie

- Config device-list: `id`, `initialName`, `address` (long-frame hex of polling-nummer), optioneel `tag`/`serial`.
- Startup: eerst elk enabled device pollen op het geconfigureerde adres; daarna polling-adressen 0–31 (of 0–63 conform manual) scannen met #11/#0.
- Matchen op long-frame address en/of tag/serial. Onbekende devices rapporteren; dubbele adressen weigeren en in de UI/log zetten.
- Een device zonder geldig adres blijft "ongeconfigureerd"; admin corrigeert `config.json` en herstart de service.

## Protocollaag

Implementatie exact volgens `docs/541-C-053-AAA.pdf`:

- Frame: preamble (0xFF), start character, address (long frame 5 bytes of short frame 1 byte, conform manual), command, byte count, status, data, checksum (XOR).
- Character coding: 8 databits, odd parity, 1 stopbit.
- Baudrate: uit 5850S-dipswitch (1200–38400; default 9600). Converter moet exact matchen.
- TCP is een stream: frames opnieuw samenstellen uit de buffer op preamble/start; nooit aannemen dat één TCP-read = één HART-frame.
- Elke response valideren op address en command; mismatches en late frames weggooien en als timeout/retry behandelen.
- Addressing: long-frame addressing (of short-frame indien de 5850S-manual dat voorschrijft); device-address ontdekken met command #11; config map name → address bytes (5 bytes lang, 1 byte kort).
- Commandosubset (feature-detect per device; 5850S-firmware kan afwijken van GF40/80/SLA):
  - Read-only: #0 unique identifier, #1 primary variable, #2 primary variable + %, #3 dynamic variables, #13 tag/descriptor/date, #48 additional transmitter status, #150 process gas type, #151 gas density/flow reference/range, #152 full scale, #190 STP, #193 operational settings, #230 valve override status, #235 setpoint, #237 valve control value, #240–#242 totalizer, #245 read alarm enable, #247 read high/low flow alarm; #131 serial, #132 model, #134 software revision indien ondersteund (fallback #0/#13)
  - Read/write: #37 primary variable lower range, #128 write-protect mode, #195 gas calibration, #196 flow unit, #197 temperature unit, #215/#216 setpoint source, #218/#219 softstart, #220/#221 PID, #222/#223 valve range/offset, #231 valve override, #236 setpoint, #246 write alarm enable, #248 write high/low flow alarm
  - #191 (STP schrijven) en #241 (totalizer reset) vallen buiten de MVP; alleen lezen.
  - #6 (write polling address) niet schrijven; alleen gebruiken voor discovery. Polling-adres wijzigen is buiten scope, net als baudrate.
- Dataformaten exact volgens manual: 8-bit uint, 24-bit uint, IEEE 754 float, ASCII en packed-ASCII; niet overal float aannemen.
- Cross-check: de 4800-serie S-protocol-manual (541B136AAG) beschrijft dezelfde commandostruktuur; `541-C-053-AAA` blijft leidend.
- Statusbytes in elk antwoord parseren voor alarm/fault; statusbadge per device.
- Setpoint source: #215 lezen; admin kan #216 schrijven. Als #215 "analog" meldt, toont de UI een waarschuwing; operator ziet de source read-only en krijgt bij een digitale setpoint-write een expliciete bevestiging dat de source naar digital kan omslaan.
- Analoge VOR-input overrules digitale valve override; status tonen als analog override actief is.
- Write-protect-antwoorden en response codes netjes afhandelen; UI toont "write protected" in plaats van een generieke fout. Admin kan #128 gebruiken om write-protect te lezen/aan/uit te zetten; elke wijziging wordt geaudit.
- Na een setpoint-write (#236) readback via #235/#237; na valve override (#231) readback via #230; na config-write de relevante read-commands opnieuw uitvoeren.
- Engineering-unit setpoints alleen toestaan in de flow-unit die het device op dat moment gebruikt; UI toont de unit en blokkeert mismatch.
- Eén outstanding transaction tegelijk; timeout 500 ms; 2 retries; na 3 fouten device offline; exponentiële reconnect voor TCP.
- Per poll-cyclus een tijd-budget: na een timeout direct door naar het volgende device, zodat één traag device de 1 Hz-cyclus niet ophoudt.
- Golden-frame tests op de voorbeelden uit de manual (o.a. flow 0.8502 L/min en setpoint 85%).

## Polling en runtime-state

Per device: flow, eenheid, setpoint, setpoint-unit, valve position, temperatuur, totalizer, status/alarm bits, online, lastSeen.

- 1 Hz per device, sequentieel; writes krijgen voorrang en pauzeren de poll-queue.
- Per-device poll-interval uit SQLite (default 1000 ms); disabled devices overslaan.
- Stale-marker in UI als lastSeen > 3 s; device offline na 3 mislukte transacties.
- Reconnect/backoff voor converter; keepalive op de TCP-socket.
- Bij startup: config laden, device-adressen scannen (#11) met per-adres timeout, onbekende of dubbele adressen rapporteren; de service start ook als de converter of bus nog niet beschikbaar is en markeert devices offline.
- Device-info (model, serial, firmware, tag) cachen in SQLite; verversen via `POST /devices/:id/refresh` of bij openen van device-detail.
- Runtime-state in geheugen; alleen audit/users/device-overrides en device-info-cache persistent.

## API en WebSocket

REST onder `/api/v1` (JSON, cookie-auth):

- `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`
- `GET/POST /users`, `PATCH /users/:id` (role/active) — admin
- `GET /devices`, `GET /devices/:id`
- `PATCH /devices/:id` `{name?, enabled?, pollIntervalMs?}` — admin
- `POST /devices/:id/setpoint` `{value, unit: "%" | "engineering"}`
- `POST /devices/:id/valve-override` `{mode: "normal" | "open" | "closed"}`
- `POST /devices/:id/config` `{gas?, flowUnit?, tempUnit?, alarmHigh?, alarmLow?, pid?, softstart?, valveRange?, valveOffset?, setpointSource?: "analog" | "digital", writeProtect?: boolean}` — admin
- `POST /devices/:id/refresh` — admin, herlees identiteit/config
- `GET /audit?limit=&deviceId=`, `GET /audit/export.csv` — admin
- `GET /health` — converter, device-count, last poll, version. Geen converter-config endpoints.

WebSocket `/ws`:

- Server pusht elke seconde `{type:"state", devices:[...]}` en `{type:"connection", state:"online|degraded|offline"}`; bij connect stuurt de server direct de laatste bekende state.
- Client stuurt alleen ping/reconnect; schrijfacties lopen via REST; reconnect met backoff.
- Cookie-auth op de upgrade; origin-check; geen CORS voor andere origins.

## Auth en RBAC

- Users in SQLite: username, passwordHash (Bun.password), role, active, lastLogin.
- Bootstrap admin via env `FLOWHUB_ADMIN_USER` / `FLOWHUB_ADMIN_PASSWORD` bij eerste start; ontbreekt dit, dan stopt de service met een duidelijke fout.
- Session: signed HTTP-only cookie, SameSite=Strict, Secure, 12 uur; `FLOWHUB_SESSION_SECRET` env.
- CSRF: SameSite=Strict + JSON-only writes + same-origin; optioneel CSRF-token.
- Wachtwoordbeleid: minimaal 10 tekens; login rate-limit 5 pogingen per 5 minuten per IP+gebruiker.
- Operator: lezen, setpoint schrijven, valve override met bevestiging.
- Admin: alles, inclusief user-admin, device-instellingen, deviceconfiguratie (met expliciete bevestiging) en audit-export.
- User-admin: aanmaken, deactiveren, rol wijzigen; geen wachtwoordreset/self-service. Audit van accountacties.

## Audit

Append-only tabel: timestamp, user, role, action, deviceId, field, oldValue, newValue, success, detail.

- Loggen: login/logout (ook mislukte logins zonder wachtwoord), user-admin, setpoint, setpoint-source, valve override, configwijzigingen (incl. write-protect), mislukte schrijfacties.
- UI: filter op device/actie; export CSV (admin), met escaping.
- Retentie: minimaal 2 jaar; optionele prune-job.
- Geen update/delete-endpoints voor audit.

## UI

- Login.
- Dashboard: table/cards met flow, setpoint, valve, temperatuur, statusbadge; online/stale; 1 Hz updates; connection banner.
- Device detail: setpoint met eenheid-toggle en bevestiging; valve override met bevestiging; setpoint-source-waarschuwing (operator read-only, admin kan wijzigen); analog-override-indicator; write-protect-status (admin kan aan/uit); device-info (model, serial, firmware, tag); statusdetail; config-formulieren (admin, met old/new-overzicht); live sparkline van de laatste ~60 s in geheugen.
- Device settings (admin): naam, enabled, poll-interval.
- User admin (admin): gebruikers aanmaken/deactiveren/rol wijzigen.
- Auditlog-viewer met paginering (default 100) en export (admin).
- Eén WebSocket-context; geen client-side polling; reconnect met backoff en verbindingstoestand in de UI.
- Writes wachten op serverbevestiging/readback; knoppen disabled zolang een write pending is; fouten als toast/banner.
- Responsive voor Edge/Chrome op Windows; geen client-installatie.
- NL-locale voor getallen en datums; API gebruikt punt-decimaal en ISO-8601.
- UI toont lokale tijd; server en auditlog werken in UTC.

## Deployment

`docker-compose.yml`:

- `app`: Bun-runtime, multi-stage build, non-root, healthcheck; `bun:sqlite` in `/data`; `config.json` read-only.
- `caddy`: reverse proxy naar `app:8080`; `tls internal` voor `flowhub.lan`; WebSocket, security headers en CSP.
- Volumes: `flowhub-data`, `caddy_data`, `caddy_config`.
- Eén app-replica; alleen die container opent de converter-verbinding.
- Bun-versie pinnen in Dockerfile en `package.json`.
- CI bouwt het Docker-image als validatie; GHCR-push is optioneel. De IPC bouwt lokaal (`docker compose build`) of trekt een private GHCR-image na `docker login ghcr.io`.
- Image tag `flowhub:<git-sha>`; rollback via de vorige tag.
- Structured JSON-logs naar stdout; Docker log-rotation (max-size 10m, max-file 5).
- Read-only root filesystem waar mogelijk; app draait als non-root.

Caddy:


Windows-clients (standalone):

- Root CA installeren: `caddy_data/caddy/pki/authorities/local/root.crt` → Trusted Root Certification Authorities.
- `flowhub.lan` in hosts-file (`%SystemRoot%\System32\drivers\etc\hosts`) of via interne DNS naar de IPC-IP.

IPC/converter:

- IPC: statisch IP, NTP, firewall alleen 80/443, tijdzone UTC, geïsoleerd VLAN zonder internet.
- Converter: statisch IP, TCP server, transparante hex-mode, baud/parity/stopbits conform 5850S, 120Ω-termination, daisy-chain (geen ster), no-data reboot uitschakelen of heartbeat voorzien. Configuratie vooraf via webinterface; app beheert dit niet.
- RS-485: shielded twisted pair, daisy-chain, 120Ω terminatie aan beide uiteinden, fail-safe bias volgens manual, shield aan één zijde aarden.
- Documenteer converter-instellingen in `docs/converter-setup.md`.

Backup:

- Dagelijkse `VACUUM INTO`/`.backup` naar `/data/backups`, 30 dagen retentie.
- Restore-stappen in `docs/restore.md`; test één keer vóór cutover.

## Operatie

- Startup: config laden (fail-fast), migraties uitvoeren, admin-bootstrap, TCP-verbinding openen (retry/backoff), device-registry scannen, polling starten, daarna HTTP/WS-server starten; de server start ook als de bus offline is.
- Graceful shutdown: polling stoppen, TCP-socket sluiten, SQLite netjes sluiten.
- Foutafhandeling: consistente JSON-errors, geen stacktraces naar de client, correlation-id in logs; Zod-validatie voor config en API; een migratie- of config-fout stopt de service met een duidelijke logregel.
- Codekwaliteit: TypeScript strict, ESLint + Prettier, Bun test + Playwright.
- Device-replacement: nieuw device-adres in `config.json` zetten, admin maakt het device aan/activeert, app scant en verifieert tag/serial; oude device deactiveren.
- Backup- en restore-acties worden gelogd; een restore wordt ook in het auditlog opgenomen.
- Opleiding/overdracht: operator- en admin-runbook, plus een korte hands-on sessie vóór cutover.

## Validatie

1. Unit tests: codec, checksum, parity, short/long address, golden frames uit de manual, stream-reassembly.
2. Simulator (`tools/simulator`): fake S-protocol TCP-device voor discovery, polling, timeouts, writes, config en write-protect.
3. Benchtest: één 5850S via converter; alle commandosubset verifiëren en vergelijken met SmartDDE-readings.
4. Full-bus test: alle devices, 1 Hz, 24 uur soak; reconnect en geheugen/CPU controleren.
5. Failure injection: converter los, device uit, verkeerde parity, dubbel adres, write-protect.
6. UI E2E (Playwright) met mock WebSocket: login, setpoint, valve override, config met bevestiging, user-admin, audit. **Lokaal niet uitvoerbaar** (geen browsers geïnstalleerd, geen Docker in deze sandbox): `npx playwright install chromium` of alleen in CI laten draaien.
7. Auth/RBAC/CSRF-tests: operator/admin-rollen, rate-limit, audit-paden.
8. Backup/restore-test.
9. Acceptatie: operator leest alle devices, schrijft setpoint, ziet de setpoint-source-waarschuwing, gebruikt valve override, wijzigt gas/unit/alarm/PID, admin beheert gebruikers en setpoint-source, audit toont juiste old/new-waarden.
10. CI: lint, typecheck, test en Docker build zijn groen op `main`. Docker is in deze sandbox niet beschikbaar; de Docker-build wordt alleen door GitHub Actions gevalideerd.

## Risico's

- 5850S-firmware ondersteunt mogelijk niet alle commandos; feature-detect en fallback per device.
- Converter transparant mode: framing/timing en clientlimiet (8) moeten in de praktijk worden geverifieerd.
- Verkeerde converterconfig (baud/parity/stopbits, TCP server, transparant) geeft geen communicatie; leg de instellingen vast in `docs/converter-setup.md` en test ze vóór cutover.
- Caddy internal CA moet handmatig op standalone Windows-clients worden vertrouwd; documenteer exacte stappen.
- RS-485-bus: juiste terminatie/biasing en daisy-chain; één master.
- HART-timing: niet sneller pollen dan het device aankan; 1 Hz is ruim.
- Setpoint-source en analoge VOR kunnen digitale bediening overrulen; UI moet dit expliciet tonen.
- Engineering-unit mismatch kan een verkeerde setpoint schrijven; UI en API blokkeren mismatch.
- Sessie-cookie blijft na diefstal tot 12 uur geldig; logout wist de cookie, korte sessie en least-privilege-rollen beperken de impact.
- Browsercompatibiliteit: moderne Edge/Chrome; geen legacy IE.
- Back-up/restore moet vóór cutover één keer zijn getest.
- PAT-toegang: `GH_TOKEN` is een Kilo-proxytoken (`kcp1.…`) die `gh` afwijst; `gh repo create`/`gh api` zijn onbruikbaar. Deze sandbox heeft **geen private-repo-credential**: alle geslaagde git-reads waren anonieme publieke reads (`Volta-Optima` is public). Een private repo geeft hier altijd 404. Pushen naar `mvandervoort/flowhub` vereist een Kilo Cloud-workspace die aan die repo is gebonden (platform-credentials), niet een browser-actie.
- Private repo/GHCR: de IPC heeft `docker login ghcr.io` nodig als het image wordt getrokken; lokale build vermijdt dit.
- CI moet op de GitHub-runner werken (Docker build zonder GHCR-push is voldoende voor validatie).
