# FlowHub — review, hiaten en herstelplan

Status: geïmplementeerd, gepusht op `kilo/jade-frame-nk1`, **niet** op hardware
getest. Deze review is de leidende planning; de product-/ontwerpspecificatie
staat in de repo (`flowhub/docs/plan.md`, `flowhub/docs/s-protocol.md`), de
operationele start in `flowhub/docs/getting-started.md`.

## Beoordeling in één alinea

De structuur is gezond: heldere scheiding tussen codec, transport, polling,
API, UI en ops. De UI, de simulatie-opstelling en de documentatie zijn bruikbaar
en de happy path is end-to-end bewezen. Het probleem zit niet in de opzet maar
in **conformiteit en afronding**: meerdere decoders wijken af van de
protocolreferentie, het schrijfpad is niet geserialiseerd ten opzichte van de
poller, enkele plan-eisen zijn niet gebouwd, en de CI is dood omdat de workflow
op de verkeerde plek staat. Dit is te repareren zonder herontwerp.

## P0 — protocolafwijkingen die apparaten verkeerd laten reageren

1. **#196-write stuurt 1 byte, protocol eist 2.**
   `pollEngine.ts:322-325` stuurt alleen `flowUnit`; `s-protocol.md:160` eist
   `flow ref(uint8), flow unit(uint8)`. Dit is de gevaarlijkste fout: een
   eenheidswijziging kan op het device verkeerd landen of met een statusfout
   worden geweigerd, terwijl de UI "opgeslagen" meldt.
2. **#237 wordt als float32 gedecodeerd, protocol zegt uint24.**
   `pollEngine.ts:234-237` doet `decodeFloat(data, 0)`; `s-protocol.md:118`
   zegt `valve control value (uint24)` = 3 bytes. `decodeFloat`
   (`sProtocol.ts:144-146`) geeft bij een te korte payload **`NaN`**, dus geen
   crash maar een kleppositie die altijd leeg/`null` is. Voor een MFC is een
   stille `null` op de kleppositie erger dan een foutmelding.
3. **`refreshDevice` gebruikt #11 zonder tag.**
   `pollEngine.ts:240-251` verstuurt #11 met lege data; `s-protocol.md:69,89`
   vereist een 6-byte packed-ASCII tag. Voor identificatie hoort **#0** te
   worden gebruikt (geen requestdata). Vermoedelijk antwoordt een echt device
   met een statusfout, waardoor device-info nooit wordt gevuld en een
   handmatige refresh faalt.
4. **Setpoint-eenheid is verkeerd gelabeld.**
   `s-protocol.md:144-150`: #235 levert `setp%` op #1-4 en `setp in flow unit`
   op #6-9. `pollEngine.ts:224-227` gebruikt de flow-unitcode (#5) als label bij
   de procentwaarde → UI toont "85 L/min" waar 85 % bedoeld is. Dit is een
   verkeerd-heden-risico bij een MFC.
5. **De simulator bevestigt de code in plaats van het protocol.**
   `tools/simulator/index.ts` is geschreven op de aannames van de client
   (float32 voor #237, 6-byte #235, 1-byte #196). Daardoor kunnen fouten 1-4
   nooit door tests worden gevangen. De simulator moet de **doc** volgen, niet
   de client.

## P0 — schrijfacties falen willekeurig

6. **Geen serialisatie tussen polling en writes.**
   `tcp.ts:106-108` weigert een tweede transactie ("A protocol transaction is
   already in progress"). De poller draait continu (4 requests per device per
   seconde) en `pollEngine.ts:204-217` doet niets aan wachtrij of retry. Een
   setpoint-write of klepactie faalt daardoor met een 400 die voor de operator
   niet te begrijpen is. Nodig: één write-queue/mutex in de engine (poll pauzeert
   of write wacht), plus een retry met korte backoff.

## P1 — functionele hiaten t.o.v. het plan

7. **`pollIntervalMs` per device wordt opgeslagen maar nooit gebruikt.**
   `pollEngine.ts:141-152` gebruikt alleen de globale `bus.pollIntervalMs`;
   `devices.poll_interval_ms` is dode data, terwijl de UI het admin-only
   instelbaar maakt.
8. **Setpoint-source wordt nooit getoond.** Het plan eist dat de operator ziet
   of de bron analoog of digitaal is, met waarschuwing. Er is geen read van
   #215/#216; de UI toont alleen een admin-select zonder de huidige waarde.
9. **`device_info`-kolommen matchen de UI niet.**
   DB: `model, serial, tag, firmware, hardware, manufacturer_id,
   device_type_code, refreshed_at` (`001_initial.sql:62-72`). UI-type:
   `flow_unit, temp_unit, gas_type, tag, serial, updated_at`
   (`web/api.ts:29-38`). De config-kaart leest velden die nooit bestaan → altijd
   leeg.
10. **`last_login` blijft altijd null.** `touchLastLogin` (`db.ts:89`) wordt
    nergens aangeroepen; de gebruikerslijst toont altijd "—".
11. **Config-endpoint negeert stil velden.**
    `api/devices.ts:20-32` accepteert `gas, alarmHigh, alarmLow, pid,
    softstart, valveRange, valveOffset`; `:193-198` geeft alleen
    `flowUnit/tempUnit/setpointSource/writeProtect` door. Ofwel implementeren
    (#150, #246, #248, #218-#223), ofwel uit het schema en de UI halen.
12. **Audit heeft geen paginering.** `api/audit.ts:12-19` kent alleen `limit`,
    zonder maximum en zonder offset. Plan vraagt paginering.
13. **UI heeft geen WebSocket-reconnect.** `web/App.tsx` (WS-effect) heeft geen
    `onclose`/backoff; bij een netwerkhapering bevriest het dashboard stil tot
    een reload.
14. **Discovery en adresvalidatie ontbreken.**
    - Geen scan van polling-adressen 0-31 (plan §Discovery).
    - Geen detectie/weigering van dubbele adressen.
    - `parseAddress` gooit in `reloadDevices` (`pollEngine.ts:119-130`); één
      typefout in `config.json` laat de **hele app** crashen bij de start in
      plaats van één device te markeren als ongeconfigureerd.

## P1 — deploy en CI

15. **De CI draait nooit.** `.github/workflows/ci.yml` staat in
    `flowhub/.github/`; GitHub leest alleen `/.github/workflows/` in de
    repo-root. Bovendien draaien alle stappen in de root terwijl `package.json`
    in `flowhub/` staat (geen `working-directory`). Verplaats naar
    `/.github/workflows/flowhub.yml` met `defaults.run.working-directory:
    flowhub`, `paths: ['flowhub/**']`, en `docker build flowhub`.
16. **Playwright is dood.** `playwright.config.ts:4` wijst naar
    `tests/e2e` (bestaat niet) en `webServer` start de app zonder
    `FLOWHUB_CONFIG`/admin-env, dus de server stopt direct.
17. **`config.json` is niet genegeerd.** Staat niet in `.gitignore` en niet in
    `.dockerignore` → risico dat echte IP's en device-adressen in git of in de
    image belanden. Toevoegen aan beide.
18. **Compose mist productiehardening.** Geen `logging.options.max-size`
    (plan eist log-rotatie), geen `read_only`, geen `cap_drop`, geen
    `security_opt`.
19. **Geen HTTP→HTTPS-redirect.** Poort 80 wordt niet gepubliceerd en Caddy
    heeft `auto_https disable_redirects`; `flowhub.lan` intypen zonder schema
    geeft een weigering.

## P2 — hardening

20. **Rate limiting is omzeilbaar.** `auth.ts:93-97` vertrouwt
    `X-Forwarded-For` onvoorwaardelijk en `api/auth.ts:41` keyt op
    `ip:username`; wisselende usernames omzeilen de limiet.
21. **Rate-limiter lekt geheugen.** `Map` in `auth.ts:101-126` wordt nooit
    opgeruimd; veel unieke keys = onbegrensde groei.
22. **Sessies zijn niet intrekbaar.** `auth.ts:27-51`: logout wist de cookie,
    maar het token blijft 12 uur geldig.
23. **Mogelijke path traversal in de statische server.**
    `index.ts:83-88` joint `dist` met `path.slice(1)` zonder containment-check.
24. **Zwakke default secret.** `index.ts:22` valt terug op
    `"dev-secret-change-me"`; in productie zou de app moeten weigeren te starten.
25. **Geen JSON-logging/correlation-id.** Plan eist dit; nu `console.log`.
26. **CSV-export is gevoelig voor formule-injectie** (`api/audit.ts`).
27. **Offline devices houden oude waarden.** `markDeviceOffline` (`db.ts:244`)
    zet alleen `online = 0`; flow/setpoint blijven staan en de UI toont ze.

## Herstelplan (in deze volgorde)

### Blok A — protocol conform de doc (P0 1-5)
1. #196-write: 2 bytes (`flow reference`, `flow unit`); flow reference uit de
   laatst gelezen #196/#235. Readback verplicht (doc §5.4).
2. `readValveControl`: `decodeUint24(data, 0)` in plaats van `decodeFloat`;
   `uint24` is al beschikbaar in de codec.
3. `refreshDevice`: gebruik **#0** (geen data) voor identiteit; #11 alleen met
   tag.
4. Setpoint-model splitsen: `setpointPercent` (uit #1-4) en
   `setpointInFlowUnit` (uit #6-9, float32) naast elkaar; UI toont beide met
   expliciete eenheid.
5. **Simulator herschrijven naar de doc** (uint24 voor #237, 10-byte #235,
   2-byte #196, 12-byte #0/#11) en golden-frame tests toevoegen per commando,
   inclusief een write/readback-ronde.
6. Benchvalidatie: één 5850S, alle gebruikte commando's vergelijken met het
   display en met een ruwe capture.

### Blok B — schrijfpad (P0 6)
7. Eén `WriteQueue` in `PollEngine`: writes krijgen prioriteit, de pollcyclus
   wacht of wordt onderbroken tussen twee transacties; retry 2× met 150 ms.
8. API geeft bij blijvende drukte een begrijpelijke `503 device_busy` in plaats
   van de interne transactiefout.
9. Audit de write altijd, ook bij falen (dat gebeurt al) en voeg `durationMs`
   toe.

### Blok C — functionele hiaten (P1 7-14)
10. Per-device `poll_interval_ms` echt respecteren (volgende-poll-tijdstip per
    device) of het veld uit API/UI verwijderen. **Advies: respecteren.**
11. Setpoint-source lezen (#215/#216) en read-only tonen aan operator met
    waarschuwing bij `analog`.
12. `device_info` gelijktrekken: UI-type uitlijnen op de DB-kolommen
    (model/serial/tag/firmware/hardware) en de config-kaart daarop baseren.
13. `touchLastLogin` aanroepen bij geslaagde login.
14. Config-endpoint: óf de extra velden implementeren, óf uit schema en UI
    verwijderen. **Advies: verwijderen** tot de bench ze bevestigt.
15. Audit: `limit` clampen (max 500) + `offset`; UI-paginering.
16. WebSocket-reconnect met exponentiële backoff en een "verbinding
    verbroken"-indicator in de UI.
17. Adresfouten niet-fataal maken: `reloadDevices` vangt `parseAddress`, slaat
    het device over met status `misconfigured`, en logt/audit dat. Discovery en
    dubbele-adresdetectie expliciet als **buiten scope** markeren als ze niet
    nu gebouwd worden.

### Blok D — deploy en CI (P1 15-19)
18. Workflow naar repo-root; `working-directory: flowhub`; `paths`-filter;
    Docker-build met context `flowhub`.
19. Playwright: `tests/e2e` met login/dashboard/setpoint/audit, `webServer` met
    tijdelijke data-dir, admin-env en `FLOWHUB_CONFIG` naar een testconfig;
    alleen in CI draaien.
20. `config.json` in `.gitignore` en `.dockerignore`.
21. Compose: log-rotatie, `read_only: true` + tmpfs voor `/tmp`,
    `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, en poort 80 met
    redirect in Caddy.

### Blok E — hardening (P2 20-27)
22. `X-Forwarded-For` alleen vertrouwen achter een bekende proxy (env-vlag),
    rate-limit keyen op IP én globaal.
23. Rate-limiter periodiek opschonen.
24. Sessie-intrekking: `token_version` per user in de DB, meegenomen in het
    token; verhogen bij logout/wachtwoordwijziging/deactiveren.
25. Static handler: `resolve` + containment-check tegen `DIST_DIR`.
26. Weiger te starten zonder sterke `FLOWHUB_SESSION_SECRET` in productie.
27. JSON-logs met `correlationId` per request en per pollcyclus.
28. CSV-export: cellen die met `= + - @` beginnen prefixen met `'`.
29. Offline: flow/setpoint op `null` zetten of expliciet als "laatst bekend"
    labelen in de UI.

## Open beslissingen

1. **Protocolbron volgen of op capture wachten?** Advies: de doc volgen (die is
   als gezaghebbend vastgelegd) en de bench als eindcontrole gebruiken. Wachten
   op hardware laat de bekende fout in #237 staan.
2. **Discovery (adressen 0-31 scannen) nu bouwen of schrappen?** Advies:
   schrappen uit scope; expliciete configuratie + duidelijke foutmelding is
   veiliger op een productiebus.
3. **Extra device-configuratie (gas/alarmen/PID) nu of later?** Advies: nu uit
   de UI en API halen, later toevoegen na benchbevestiging per commando.
4. **Branch naar `main` mergen?** Advies: pas na blok A en B; nu is de branch
   een werkbranch met bekende protocolfouten.

## Validatie na herstel

- Unit: golden frames per gebruikt commando, inclusief uint24-#237, 10-byte
  #235, 2-byte #196 en #0-identiteit.
- Integratie: simulator (doc-conform) + server, write tijdens actieve polling
  moet 100/100 slagen.
- Auth/RBAC: operator mag geen config/users/audit; gedeactiveerde user verliest
  direct toegang; rate limit blokkeert.
- E2E: login → dashboard → setpoint → audit, in CI.
- Bench: één 5850S, alle commando's, readback na elke write.
- Docker: `docker build flowhub` en `docker compose up` in CI respectievelijk op
  een host met Docker.

## Buiten scope (bevestigd)

Geen GMP/21 CFR Part 11, geen e-signatures, geen SIL. Noodstop blijft
hardwarematig. Geen historische trends, geen multi-bus, geen
converterbeheer door de app, geen baudrate-wijziging via protocol.
